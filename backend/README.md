# goroot_ — Backend

REST API для лендинга и личного кабинета. **Реализуется вручную** — здесь
лежит только каркас и договорённости по контракту с фронтендом.

> ⚠️ Код бэкенда в этом коммите намеренно не написан. Папка содержит README
> и `.gitignore`, чтобы фронтенд мог сразу опираться на согласованный API.

## Предполагаемый стек

- **Go** (`net/http` или `gin`)
- **PostgreSQL** + `sqlx`, миграции
- **JWT** для авторизации кабинета
- **Docker** / `docker-compose` для локального запуска

## Рекомендуемая структура

```
backend/
├── cmd/
│   └── api/
│       └── main.go          # точка входа
├── internal/
│   ├── handlers/            # HTTP-слой
│   ├── service/             # бизнес-логика
│   ├── repository/          # доступ к данным (PostgreSQL)
│   └── models/              # доменные модели
├── migrations/              # SQL-миграции
├── go.mod
├── go.sum
├── Dockerfile
└── docker-compose.yml
```

## Контракт с фронтендом

Фронтенд ожидает базовый URL в переменной `VITE_API_URL`
(см. `frontend/.env.example`). Ниже — ориентировочный набор эндпоинтов,
под которые сверстан кабинет (`frontend/src/data/cabinet.js`):

| Метод  | Путь                  | Назначение                          |
|--------|-----------------------|-------------------------------------|
| `POST` | `/api/auth/login`     | вход в кабинет, выдача JWT           |
| `GET`  | `/api/profile`        | данные профиля                      |
| `GET`  | `/api/orders`         | список заказов клиента              |
| `GET`  | `/api/orders/{id}`    | детали заказа + таймлайн            |
| `GET`  | `/api/messages`       | сообщения по проектам               |
| `POST` | `/api/leads`          | приём заявки из формы на лендинге   |

Формат ответов и модели согласуются по мере реализации. Демо-данные на
фронте лежат в `frontend/src/data/` и заменяются реальными вызовами API.

## Запуск (после реализации)

```bash
cd backend
go run ./cmd/api
# или
docker-compose up --build
```
